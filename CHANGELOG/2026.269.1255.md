# 2026.269.1255 — fix(scaffold): drop the tracked generated artifacts + the template's bogus gate

## Summary of changes

Corrects the repo scaffold that the `main` bootstrap seeded into this new repo. The
bootstrap (`opencharly/.github` `bootstrap-repo-main.yml` → `scripts/bootstrap-repo-main.sh`)
creates the first protected `main` **from the already-pushed `feat/cua` head** — so `main`
began carrying the feature-branch content verbatim, including four scaffold defects copied
from the `plugin-jetkvm` template.

The concrete edits:
- **Del `.github/workflows/ci.yml`** — copied from `plugin-jetkvm`; it referenced
  `candy/plugin-jetkvm/go.mod` / `go.sum`, a path that does not exist in this **candy-only**
  repo (it ships no Go module at all), so the gate would have failed on every run.
- **Del `.build/cua-driver-test/Containerfile`, `.containerignore`, `.dockerignore`** — all
  three carry a `generated -- do not edit` header (charly recreates them from `charly.yml`
  on every generate/build), and **none of the 7 audited canonical candy repos track any of
  them**.
- **Add `.gitignore`** — the canonical charly-generated-artifact patterns; its absence is
  why those three generated files were committed.
- **`deploy.yml`** — pin `v2026.258.0219` → `v2026.269.1034`.

The five candy manifests (`cua-driver`, `cua-session`, `cua-computer-server`, `cua-guest`,
`cua-hyprland-plugin`) and the build bed are already on `main` via the bootstrap seed; this
PR is the scaffold correction on top.
